# Tetherly v0.4.0 — 跨屏原生拖拽

v0.3.x 系列（v0.3.0 – v0.3.5）收官的里程碑版本。从 Mac 拖文件或文件夹越过屏幕边缘后，在 Windows 侧它就是鼠标正拖着的真实文件，可以直接放进资源管理器、桌面或任意应用。

## 亮点

- **接收端原生拖拽**（v0.3.0）：新增 `RemoteDragPull` 协议，由 `dragpull` 能力门控。光标一过边，发送端就开始预传。Windows 侧拉起 `tetherly drag-source` helper，走 OLE `DoDragDrop`（CF_HDROP，仅 COPY），文件全部落盘后才放行 drop。没落到目标或按了 Esc，文件进下载目录并选中。
- **SHA-256 接收去重**（v0.3.1）：接收端已有相同内容（sha256 和大小都一致）时按 `resume_from = total` 接收，发送端零字节完成，本地用硬链接交付。
- **文件夹拖拽**（v0.3.3 / v0.3.4）：文件夹打包成单个 tar 传输（`FileMeta.bundle = "dir-tar"`）。接收端安全解包，只建普通文件和目录、不跟随符号链接、不会写到目标目录外，并逐文件打 MOTW。由 `dragdir` 能力门控，可以走原生拖拽。
- **稳定性**：
  - v0.3.1：修复落进应用时报 OLE E_FAIL 的问题。
  - v0.3.2：helper 加看门狗；deploy 改为按命令行选中 daemon。
  - 回到本机的 carry 不会被二次接管。
  - DoDragDrop 被拒时会重试。
  - 轮询提速，角标静止时不再反复重设位置。
- **v0.3.5 review 修复**：
  - 去重缓存与交付副本共享 inode：副本被原地改写后，缓存会重新哈希核验，不再按原 sha 命中。
  - 文件夹解包不完整时有提示，不再静默报成功。

## 兼容性

- 新消息和新语义都有能力门控，旧版本对端会自动回落到 v0.2.x 拖拽路径（下载目录 + 选中）。
- 对旧接收端来说，`FileMeta.bundle` 是可选字段，它们收到的是可用的 `.tar` 文件。
- 在 Windows 上设置 `TETHERLY_NO_NATIVE_DRAG=1` 可以关闭原生拖拽。
