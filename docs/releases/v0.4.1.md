# Tetherly v0.4.1 — 流式文件夹 + 拖拽 helper 根因修复

收掉 v0.4.0 交接文档 §6 遗留的两项。

## 亮点

- **文件夹流式发送**（75743e0）：对端带 `filestream` 能力时，文件夹不再先完整打包到 staging。
  - 发送端只扫描目录，offer 里预告大小，接受后边生成 tar 边发，SHA-256 放在流尾经 AEAD 封装的 trailer 里。
  - 效果：GB 级文件夹没有首帧打包等待，也不再额外占一份等大磁盘。
  - 支持断点续传：重新生成 tar 跳过已保留的前缀，接收端重新哈希 `.part` 前缀。
  - 扫描后文件夹被改动会导致摘要不符，此时拒绝安装。
- **原生拖拽 helper 卡死根因修复**（f258a6c）：
  - 根因：拖回再拖入使同一 drag 被接管两次。两个 helper 抢 OLE，后者 E_FAIL 并把整个 drag 判失败；前者在指针静止时滞留 `DoDragDrop` 数秒，又让下一次拖拽也 E_FAIL。
  - 修复：
    - 每次接管分配 helper session nonce，被取代的 helper 读到 cancel，结果不计。
    - daemon 已有决定（取消、失败，或已松手且文件就绪）时，向 helper 自己的线程投递一次 `WM_MOUSEMOVE` 唤醒 OLE 循环，不向桌面注入输入。
    - `QueryContinueDrag` 的计数、空闲时长和唤醒次数写进日志，方便下次排障。
- 其他：清理无用依赖和脚本；崩溃残留的解包目录会被清扫；文件夹大小上限计入 tar 开销；打包时同步哈希。

## 兼容性

- `filestream` 由能力门控，旧对端仍走 `pack_dir` staging 路径。
- `NativeDragRequest.session` 是可选字段，不带 session 的旧 helper 照常服务。
- 已知限制：流式发送的文件夹在 outbox 里不能"重发"，需要重新拖一次。
